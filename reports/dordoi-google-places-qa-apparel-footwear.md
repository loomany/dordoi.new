## 3. `excluded` (94)

### Распределение по `exclusionReason`

| Причина | Кол-во |
|---------|--------|
| `distance>1500m` | **78** |
| `unclassified_primary_type` | **12** |
| `blacklist_primaryType:supermarket` | **1** |
| `blacklist_keyword:школ` | **1** |
| `blacklist_type:food` | **1** |
| `blacklist_type:health` | **1** |

### Кафе / банки / карго / логистика / аптеки

В **этом** срезе **нет** исключений с явными `blacklist` причинами вроде cafe/bank/pharmacy/cargo из короткой выборки: сработали **supermarket**, **школ** в тексте, вторичный тип **food**, тип **health** у обуви.

- **Супермаркет:** «**ЭкспортАзия**» — типичный оптовый «маркет» на Дордое; blacklist **логичен** для чистоты apparel, но бизнес может хотеть отдельный вертикаль «продукты оптом».  
- **«школ»:** «**Wealth Канцтовары … товары для школы оптом**» — **ложное срабатывание** по подстроке (канцтовары для школ ≠ школа как учреждение).  
- **food:** «**Сотовых аксессуаров**» (есть `food`/`food_store` в типах Google) — **вероятный false negative** для аксессуаров.  
- **health + обувь:** «**Orthopedic**» (`shoe_store` + тип `health`) — **спорно**: ортопедическая обувь может быть целевой для каталога обуви.

### False negative — список к проверке вручную

| title | reason | Комментарий |
|-------|--------|---------------|
| **Wealth Канцтовары …** | `blacklist_keyword:школ` | Канцтовары; ослабить правило или исключать по контексту «для школы оптом». |
| **Сотовых аксессуаров** | `blacklist_type:food` | Похоже на аксессуары; тип `food` от Google — **whitelist по названию** или игнор `food` если primary не food. |
| **Orthopedic** | `blacklist_type:health` | Обувь; рассмотреть исключение для `shoe_store` + health. |
| **ЭкспортАзия** | `blacklist_primaryType:supermarket` | Корректно для apparel-фильтра; не ошибка, а **trade-off**. |
| **EL elvira** | `unclassified_primary_type` | `clothing_store` в types, **пустой** `primaryType` — **баг классификатора** (должны уметь матчить по types). |
| **Ansari - мусульманская одежда…** | `unclassified_primary_type` | Аналогично — **одежда**, пустой primary. |
| **Мир Футбола.** | `unclassified_primary_type` | `sporting_goods_store` — можно маппить в спорт/обувь при политике сайта. |
| **Дордой Автозапчасти** | `unclassified_primary_type` | Корректно исключить из apparel. |
| **BEK MEGA BISHKEK**, **DOSTLUK TEXTILE**, **LETO textile**, **MILLER TEXTILE**, **𝐌𝐈𝐋𝐋𝐄𝐑 𝐓𝐄𝐗𝐓𝐈𝐋𝐄** | `unclassified_primary_type` | Текстиль/`home_goods_store` — **полезно для «ткани»**, не для apparel-ветки; лучше `discovery_unmapped` с категорией ткани, чем excluded. |
| **Yasin Tv** | `unclassified_primary_type` | Электроника — ок в excluded для apparel. |

**Итого явных кандидатов на доработку правил:** минимум **4–6** записей (Wealth, Сотовых аксессуаров, Orthopedic, EL elvira, Ansari, плюс текстильные home_goods как продуктовая политика).

## 4. Рекомендации по blacklist / positive-classifier

| Область | Предложение |
|---------|--------------|
| **Positive keywords** | «детск» не должен перетягивать **детскую обувь** в `toys`; добавить ветку/правило **детская обувь → footwear / children**. |
| **Классификация после blacklist** | Если `primaryType` пустой, но в `types` есть `clothing_store` / `shoe_store` — матчить каталог или `discovery_unmapped` с осмысленной причиной, а не `unclassified_primary_type`. |
| **Blacklist keyword «школ»** | Сузить до учреждений или исключить контекст «канц… школы оптом». |
| **Blacklist type `food`** | Не отсекать, если `primaryType` не про еду и название про аксессуары/электронику. |
| **`health` + `shoe_store`** | Разрешить или сниффер по названию (orthopedic / ортопед). |

## 5. Запускать ли следующую discovery-группу?

**Да, разумно** — после:

1. Подтверждения, что **Places API (New)** стабильно отвечает без `API_KEY_SERVICE_BLOCKED` (или документирования «дырявого» прогона).  
2. Микроправок классификатора по **пустому primaryType** и **детская обувь ≠ toys** (можно в отдельном PR; этот документ только QA).

Следующая логичная группа по плану сбора рынка: **`trade-market`** (широкий охват `store`/`market`) — дополняет apparel и даст больше `generic-retail` для калибровки.

## 6. `apiErrors` (без повторных запросов)

### Что падало

- **Places SearchText** — метод `google.maps.places.v1.Places.SearchText`, хост `places.googleapis.com`.  
- **Places SearchNearby** — метод `google.maps.places.v1.Places.SearchNearby`, тот же хост.

### Сколько

- **Всего записей в `apiErrors`:** 13  
- **SearchText (префикс `text:`):** 8  
- **SearchNearby (префикс `nearby:`):** 5  

### Упавшие запросы (из сохранённого JSON)

**Text:** `оптом Дордой`, `wholesale Bishkek`, `одежда оптом Бишкек`, `фурнитура Бишкек`, `товары для дома Бишкек`, `мебель Бишкек`, `посуда Бишкек`, `электроника Бишкек`.

**Nearby (метки):** центр C и точки S/E на радиусах 500 и 700 м (часть сетки вернулась с ошибкой).

### code / message / status (типовой ответ)

- **code:** `403`  
- **status:** `PERMISSION_DENIED`  
- **message (смысл):** запросы к указанному методу Places **заблокированы** для ключа.  
- **ErrorInfo.reason:** `API_KEY_SERVICE_BLOCKED`  

### Нужен ли retry через 5–10 минут?

Для **`API_KEY_SERVICE_BLOCKED`** retry по таймеру **сам по себе не лечит**: сначала должны примениться настройки ключа и квот в Google Cloud. **Имеет смысл** повторить **тот же** прогон через **5–10 минут после сохранения** ограничений API, если вы только что включили Places API (New) и обновили restrictions — иногда задержка распространения **минуты**. Если после повтора снова 403 — проблема в конфигурации ключа, а не во времени.
