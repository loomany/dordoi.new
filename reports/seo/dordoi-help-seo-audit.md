# SEO-аудит: dordoi.help

**Дата аудита:** 2026-05-11  
**Объект:** публичный сайт https://dordoi.help  
**Ограничения:** только аудит и рекомендации; код, дизайн, auth, платежи, БД, Supabase, RLS **не менялись**.

---

## 1) Executive summary

Сайт **технически подготовлен к мультиязычному SEO** на уровне шаблона: в коде есть единый хелпер метаданных с **абсолютным canonical**, **hreflang для всех локалей одного пути**, **OpenGraph/Twitter (без картинки)**, отдельные **title/description по ключам `Seo.*` в переводах**, редирект **`/` → `/ru`**, префикс локали **всегда в URL** (`localePrefix: "always"`).

**Критический вывод для запуска платного трафика под Google:** на продакшене сейчас активен режим **полного закрытия от поисковиков**: в `robots.txt` стоит **`Disallow: /`**, в HTML — **`noindex, nofollow`**, **`sitemap.xml` отдаёт пустой `<urlset>`** (без URL). Это следует из логики `siteIndexable()` / переменной окружения **`NEXT_PUBLIC_SITE_INDEXABLE`** (в репозитории по умолчанию выключено). Пока это не переключено на проде и не проверены побочные эффекты, **индексации в Google практически не будет** — платный трафик на органику не опирается.

Дополнительно зафиксированы **SEO-риски до доработок**: **нет `og:image`**, **`x-default` указывает на URL без локали**, которые **307 на `/ru/...`** (нежелательная практика для hreflang), **`<html lang>` по умолчанию `ru`** и синхронизируется с локалью **только на клиенте**, в **sitemap не попадают динамические URL карточек каталога** (`/catalog/{slug}` из БД), коды локалей в проекте — **`kg` и `tj`**, тогда как для hreflang обычно ожидают **языковые** коды **`ky`** и **`tg`** (см. раздел 3).

## 2) Critical blockers before traffic

| # | Проблема | Доказательство (проверка) | Эффект |
|---|-----------|---------------------------|--------|
| 1 | **Полный запрет индексации** | `https://dordoi.help/robots.txt` → `User-Agent: *` + **`Disallow: /`** | Краулеры не должны индексировать публичные страницы. |
| 2 | **Meta robots noindex, nofollow** | В ответе HTML для `/ru` в потоке метаданных: **`noindex, nofollow`** | Даже при обходе robots страницы не должны попадать в индекс. |
| 3 | **Пустой sitemap** | `https://dordoi.help/sitemap.xml` → валидный XML с **пустым** `<urlset>` | Нет сигнала для Google о наборе URL; не соответствует ожиданиям «готового» запуска. |
| 4 | **Нет строки Sitemap в robots** (в текущем режиме) | В `robots.txt` нет `Sitemap: https://dordoi.help/sitemap.xml` | Снижает обнаруживаемость sitemap (после включения индексации нужно проверить снова). |

**Примечание:** при одном из запросов к `sitemap.xml` через внешний fetch наблюдался **HTTP 500**; повторная проверка через `curl` отдала **200** с пустым набором URL. Имеет смысл мониторить стабильность ответа (CDN/деплой/таймауты).

## 3) Multilingual SEO status

### 3.1 Фактические локали в проекте (не совпадают с запросом «ky / tg»)

В коде (`i18n/routing.ts`): **`ru`, `kk`, `kg`, `uz`, `tj`**. Отдельной локали **`en` нет**.

| Ожидание в ТЗ | В проекте | Комментарий для SEO |
|---------------|-----------|---------------------|
| **ky** (кыргызский) | **`kg`** | **`kg`** — код **страны** (Kyrgyzstan), не языка. Для hreflang Google рекомендует **BCP 47**: кыргызский — **`ky`**. Текущий **`hreflang="kg"`** — источник путаницы и риска некорректной кластеризации. |
| **tg** (таджикский) | **`tj`** | **`tj`** — страна (Tajikistan). Языковой код таджикского — **`tg`**. |
| **kk** (казахский) | **`kk`** | Соответствует ожиданиям. |
| **uz** | **`uz`** | Соответствует. |
| **ru** | **`ru`** | Соответствует. |

**Рекомендация (без реализации в этом аудите):** спланировать миграцию префиксов URL и hreflang на **`ky`** и **`tg`** с редиректами **301** со старых путей (`/kg/…`, `/tj/…`) — это уже продуктовое решение с риском простоя в выдаче; альтернатива — оставить URL, но **исправить только значения hreflang** (если платформа позволит развести «путь» и «языковой тег» — в стандартном next-intl это обычно связано).

### 3.2 Язык контента по файлам переводов

По выборочному просмотру `messages/*.json` блоков **`Seo.*` и `Pages.*`**: для **ru, kk, uz, tj** заголовки и описания выглядят как **отдельные переводы**, не копипаст одного русского текста. Для **`kg`** местами встречается **лексика с русскими заимствованиями** в UI (например, подписи в футере) — не критично для всего сайта, но для «идеального» мультиязычного SEO стоит вычитать носителем.

### 3.3 Английский (`en`)

**Отдельной локали нет.** Запросы вида `/en` ведут в цепочку редиректов к несуществующим путям (проверка: **`/en` → редирект на вложенный путь под `ru`**). Для международных B2B-запросов на латинице (**`Dordoi wholesale`**, экспортёры) **отдельный `en` или хотя бы англоязычные лендинги под кластер** могут дать дополнительный охват; это **P2 / стратегия**, не блокер запуска на СНГ-языках.

## 4) Indexation / robots / sitemap

### 4.1 robots.txt

- **Файл есть.**
- **`Disallow: /`** — блокирует всё дерево.
- **Строки `Sitemap:` нет** (в режиме «не индексируем» в коде `app/robots.ts` sitemap не добавляется).

### 4.2 Sitemap

- **`/sitemap.xml`** отвечает **200**, тело — **пустой urlset** (при выключенной индексации в коде возвращается **пустой массив**).
- **Сплита sitemap** (несколько файлов) **нет**.
- **`publicRoutes` в `lib/seo.ts`** покрывает только статические маршруты (`/`, `/catalog`, `/sell`, `/suppliers`, `/buyers`, …). **URL вида `/catalog/{slug}` для реальных вендоров из БД в sitemap не генерируются** — это пробел для индексации карточек продавцов.

### 4.3 Meta robots на страницах

При **`NEXT_PUBLIC_SITE_INDEXABLE !== "true"`** на страницы наслаивается **`noindex, nofollow`** (и в корневом `app/layout.tsx`, и в `buildPageMetadata` через `lib/seo.ts`).

## 5) Metadata / canonical / hreflang

### 5.1 Canonical

- В шаблоне **`buildPageMetadata`**: canonical = **`https://dordoi.help/{locale}{path}`** — **абсолютный**, на **текущую локаль**, не «всегда на русский».  
- Для **примерной карточки** `/ru/catalog/container-04-12` в HTTP **Link** также видны alternate-ссылки на другие локали — паттерн согласованный.

### 5.2 hreflang

- В метаданных генерируются **`alternate`** для **всех пяти локалей** из роутинга.
- **`x-default`:** в **HTTP Link** на ряде URL присутствует **`hreflang="x-default"`** на **`https://dordoi.help/catalog...`** (без префикса локали). Запрос **`https://dordoi.help/catalog/container-04-12`** отдаёт **307 → `https://dordoi.help/ru/catalog/container-04-12`**.  
  **Риск:** Google не рекомендует указывать в hreflang URL, которые **не отдают 200** без редиректа; **x-default на редирект** может ослабить кластер или привести к ошибкам в Search Console.
- **Взаимность:** при едином генераторе `localeAlternates` для симметричного пути ожидается симметричный набор ссылок на всех локалях (проверка выборочно по **Link** заголовкам — набор симметричен).
- **Проверка «все URL дают 200»:** пути **`/ky`**, **`/tg`**, **`/en`** **не являются** локалями приложения; **`/ky`** и **`/tg`** уходят в **редирект на вложенный путь под `/ru/...`** (некорректно для пользователя и для ожиданий ТЗ). Корректные префиксы: **`/ru`, `/kk`, `/kg`, `/uz`, `/tj`**.

### 5.3 Open Graph / Twitter

- Есть: **`og:title`**, **`og:description`**, **`og:url`**, **`og:site_name`**, **`og:locale`** и **`og:locale:alternate`**, **`twitter:card` = summary_large_image**, title/description для Twitter.
- **Нет `og:image` / `twitter:image`** в шаблоне метаданных — для **WhatsApp / Telegram / VK** превью часто **хуже или отсутствует**, чем при явной картинке 1200×630.

## 6) Content quality by language

- **RU:** title/description и H1 в `messages/ru.json` выглядят целевыми под «Дордой», B2B, каталог — **не** «Home» / «Dordoi» голым словом.
- **KK / UZ / TJ:** аналогично по структуре ключей — отдельные строки.
- **KG:** в целом кыргызский, с оговоркой про смешение/заимствования в части UI.
- **Смешение языков на одной странице:** бренд **`Dordoi.help`**, аббревиатуры **B2B**, **FAQ**, **Telegram**, **Email**, **WhatsApp** — ожидаемо; юридические тексты (terms) содержат **латиницу имён юрлиц** (например Lemon Squeezy) — нормально для юридической страницы.
- **Заглушки:** отдельных ключей «Lorem» не выявлено по выборочному просмотру SEO-ключей; при этом **малый объём FAQ (3 Q&A)** — слабый сигнал полезности для SEO.

## 7) Technical SEO / SSR / performance

### 7.1 Архитектура URL (факт)

**Вариант Б с префиксом локали:**  
`/ru`, `/ru/catalog`, `/ru/suppliers`, `/ru/buyers`, `/kk/catalog`, …  

**Корень `/`** — **редирект на дефолтную локаль** (`ru`).  
**Путь без локали `/catalog`** — **редирект** на локализованный (для краулера — не финальный канон без редиректа).

**Дублей вида одновременно индексируемых `/providers` и `/ru/providers` нет** — маршрута **`/providers` в приложении нет** (вместо этого **`/suppliers`**, **`/sell`**, **`/buyer-service`**).

### 7.2 SSR и видимость текста

- Главная **`/ru`**: размер загруженного HTML (по `curl` с `-o NUL`) порядка **~183 KB** — типично для **Next.js App Router + RSC payload**; основной маркетинговый текст и навигация **присутствуют в исходнике**, но часть разметки/данных уходит в **streamed flight** — для Google это обычно приемлемо, но **критичные meta** уже видны в теле (в т.ч. в вставках Next).
- **Следов ScholarshipTop / grants / essays** в репозитории по grep **не найдено**; на выборочной странице нет явных артефактов стороннего проекта (кроме искажения кодировки в консоли Windows при `findstr` — не атрибут сайта).

### 7.3 Ошибки HTTP (выборочно)

| URL | Результат |
|-----|-----------|
| `/ru/catalog` | **200** |
| `/ru/suppliers`, `/ru/buyers` | **200** |
| `/ru/providers`, `/ru/cargo` | **404** (маршрутов нет) |
| `/ru/catalog/womens_clothing` | **404** (категории, судя по коду, завязаны на **query**, не на path slug) |
| `/ru/catalog/container-04-12` | **200** (статический демо-slug) |

### 7.4 Производительность / Lighthouse

- **Lighthouse / PageSpeed Insights** в рамках этого аудита **не запускались** (нет сохранённого отчёта).  
- **Базово:** большой HTML, множество чанков `/_next/static/chunks/...` — ожидаемо для текущего стека; для рекомендаций по LCP/CLS нужен прогон Lighthouse на **мобильной** эмуляции из региона ЦА.

## 10) Recommended staged implementation plan

1. **Перед любым SEO-трафиком:** на проде **`NEXT_PUBLIC_SITE_INDEXABLE=true`**, перепроверить **`robots.txt`**, **meta robots**, **непустой sitemap**, отправка в **Google Search Console**, проверка **x-default** (убрать редирект или сменить x-default на **`/ru/...`**).
2. **Сразу после:** **og:image** по умолчанию + опционально per-page; **исправление hreflang кодов** (`ky`/`tg`) или осознанное принятие `kg`/`tj` с компенсацией в GSC.
3. **Расширение sitemap:** включить **опубликованные** `/catalog/{vendorSlug}` (и решить политику для демо-slug страниц).
4. **Schema:** Organization + WebSite, FAQPage, BreadcrumbList.
5. **Контент:** расширить FAQ, добавить карго-страницу при наличии данных.

## 12) Приоритеты P0 / P1 / P2

### P0 — обязательно перед запуском органики / до «SEO-готовности»

1. Включить **`NEXT_PUBLIC_SITE_INDEXABLE=true`** на **production** и проверить итоговые **`robots`**, **meta robots**, **sitemap** (не пустой).
2. Убедиться, что **`NEXT_PUBLIC_APP_URL=https://dordoi.help`** (канон, OG, sitemap).
3. **Исправить стратегию `x-default`:** либо указывать **`https://dordoi.help/ru/...`**, либо отдавать **200** на безлокалевый URL без редиректа (сложнее при `localePrefix: "always"`).
4. **Hreflang BCP 47:** решение по **`kg`→`ky`**, **`tj`→`tg`** (или осознанный риск + мониторинг в GSC).
5. Добавить **`og:image`** (и при необходимости `twitter:image`).
6. Проверить **`<html lang>` на SSR** для нерусских локалей (сейчас корень **`lang="ru"`**, смена на клиенте).

### P1 — желательно в первые 1–3 дня после открытия индексации

1. **Расширить sitemap** динамическими URL каталога (опубликованные продавцы).
2. **JSON-LD:** Organization, WebSite, FAQPage (на `/faq`), BreadcrumbList.
3. **FAQ:** расширить объём и структурированные ответы под реальные вопросы байеров/продавцов.
4. **Alt** у ключевых изображений, **width/height** для LCP-изображений (аудит не измерял каждое поле — рекомендация общая).
5. **Performance:** Lighthouse, оптимизация hero/шрифтов/лишних чанков по отчёту.

### P2 — после запуска

1. Блог / гайды по закупу на Дордое, доставке, таможне.
2. Программные страницы под **карго-направления**, **города**, **категории** (с антидублем и полезным списком).
3. **Англоязычный** слой (`en`) или отдельные лендинги под экспортные запросы.
4. Постоянный мониторинг **GSC** + **логи сервера** на предмет 404/5xx.
